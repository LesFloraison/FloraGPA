# Native mesh storage from a selected instance onward

Implementation: `aed89e545d565dbc1a9a98242e832ee1849b6e9d`.

The native mesh path can retain the vertex storage needed to reproduce the
frozen-main exports identified in `DX11_NATIVE_MESH_INSTANCE_STORAGE.md`.
Selection and retained storage have separate bounds. This is a P3 implementation;
the default backend cutover and complete RenderDoc removal remain open.

## Interface and representation

The owned request option is `vertex_storage: "remaining"`. The CLI accepts:

```powershell
build/vs2022/Release/FloraGPA.Cli.exe analyze frame.gpa_frame mesh `
  --gpa-event 1415 --stage vs-inputs --instance 1 --vertex-storage remaining `
  --gpu-vendor 0x10de --out output --timeout 180
```

The native Replay Mesh view offers **Vertices from this instance onward**.
Its existing selected-instance mode remains the default. Changing storage scope
invalidates the current result; a result for another scope cannot populate the
view. The control is disabled during work and while using the legacy backend.
The backend identity is `dx11-native/10`, invalidating earlier cached contexts.

An explicit instance is required. VS input replay, assembled VS identities and
final VS/DS/GS output retain storage. The new option does not apply to the separate
hull-phase or output-log representations; their existing paths remain available.
Existing geometry dependency checks and full-capture byte limits still apply.

| Artifact or field | Meaning |
| --- | --- |
| `vertices.bin`, `identities.json` | Existing selected-instance records and identities |
| `remaining_vertices.bin` | Raw records after the selected instance, from the same full capture |
| `remaining_identities.json` | Matching later-instance identities when available; otherwise an empty array |
| `data.vertices`, primitives and input references | Selected geometry only |
| `vertex_storage.vertices` | Selected plus later raw records, before presentation compaction |
| `vertex_storage.first_vertex` | Start of the selected range in full captured storage |
| `vertex_storage.sha256` | Digest of selected bytes followed by the additional bytes |
| `vertex_storage.full_sha256` | Original full-capture digest, also recorded by instance selection |
| `replay_mesh.vertex_sources` | Compact presentation rows mapped to the combined raw storage |
| `replay_mesh.reference_vertices` | Selected references mapped to compact presentation rows |

The selected records are not duplicated in the additional artifact. Empty
additional storage is explicit for the last instance. The receiver checks byte
counts, range arithmetic, the capture limit, selected ownership, later-instance
ordering, digests and canonical artifacts. A range starting at zero must also
match the full-capture digest. No extra GPU replay is introduced to retain bytes.
The selected-only presentation avoids copying a combined storage buffer.

Presentation compacts records by instance, original vertex identity and distinct
raw output bits. CSV and OBJ include all retained vertices; faces and indices
continue to reference only the selected instance. Nonidentified final output
keeps its captured order. CLI jobs publish canonical selected and additional
storage; compact `post_*` presentation files are generated by the shared native
Replay Mesh presentation used by the GUI and probe. CLI presentation-file parity
is a separate remaining integration task.

## Validation and reproduction

`tests/NativeReplayMeshUiTests.cpp` adds 27 GPU selections across NVIDIA, Intel
and WARP: VS input replay, assembled VS identities, terminal DS and a variable
GS, including their last instances. Tests check stored versus selected counts,
unchanged selected references, malformed metadata and identities, corrupted or
missing additional storage, mismatched UI scope, export and invalidation.

`tools/validate_native_mesh_storage.py` independently checks the retained shader
outputs. VS and GS values are checked against their synthetic shader equations.
Terminal DS vertices are checked per patch, allowing the observed tessellator
ordering. The verifier also checks artifact/context identity, CSV/OBJ data and
selected faces. Its corruptions include rehashed artifact catalogs, so an
otherwise valid catalog cannot hide incorrect additional data or ownership.

Build the CLI, GUI, Worker, native mesh probe and these test targets:

```text
FloraNativeReplayMeshUiTests FloraNativeAnalysisTests FloraPostTransformTests
FloraNativeComputeDebugTests FloraGeometryUavDependencyTests FloraReplayMeshUiTests
```

Set `QT_QPA_PLATFORM=offscreen` and put the configured Qt directory on `PATH`.
Set `FLORA_NATIVE_MESH_STORAGE_EVIDENCE` to a new directory before running the
native mesh UI suite. For the saved-report legacy UI test, set `FLORA_MESH_REPORTS`
to the retained ten-report collection. Run GPU suites and probes serially.

```powershell
python tools/validate_native_mesh_captures.py `
  --probe build/vs2022/Release/FloraNativeMeshCaptureProbe.exe `
  --qt-bin D:/Qt/6.11.2/msvc2022_64/bin --captures D:/CDXrepo/captures `
  --out artifacts/dx11-native/mesh-storage-rerun --case-set all `
  --position-channels --vertex-storage remaining
python tools/compare_native_mesh_baseline.py `
  --baseline artifacts/dx11-native/mesh-instance-baseline-records/reports `
  --native artifacts/dx11-native/mesh-storage-rerun --case-set all `
  --out artifacts/dx11-native/mesh-storage-rerun-comparison.json
```

Both commands require new output destinations. The comparison reads saved
development baselines and never launches an external analyzer. Those historical
formats are not newly required release-test inputs. Deterministic synthetic tests
and native capture probes run without RenderDoc or private GPA modules.

## Recorded results

The 27 synthetic selections pass on all three adapters. Thirty real selections
run two native jobs each, covering the ten retained GF2, BF1 and Helldivers
event/instance combinations on NVIDIA, Intel and WARP. All 60 jobs pass. Each
real selection checks both selected assembly and every retained later instance
against final stream output, including exact raw bytes. The 210 real-data
corruption controls and nine independent storage/export/context controls are
rejected. No recorded native probe or Worker module list contains RenderDoc or
private GPA modules.

All ten saved NVIDIA comparisons now match the frozen-main binary, CSV and OBJ
exports exactly. Selected indices and referenced records also match. This closes
the four observed storage omissions: BF1/1415 at instances 0, 1 and 4, and
Helldivers/200 at instance 0. The saved baseline is NVIDIA-only; Intel/WARP results
are checked against their native assembly and synthetic equations. Running the
same updated comparator against the prior selected-only additional-instance
evidence still produces the two original failures and exits 1.

The actual CLI BF1/1415/1 job produces the same context, report and all 12 canonical
artifacts as the native UI probe. It retains 7056 raw records, including the 882
selected references; presentation compacts them to 2248 stored vertices.

These 302 Qt passes include setup and cleanup rows. The two skips still require
the original shader-source capture; the saved-report legacy UI case passes.
The GUI, CLI, Worker, probe and affected test targets build successfully.

Across the 60 real-capture jobs, reported Worker execution times are 125–1730 ms
and peak working sets are 237,465,600–2,655,694,848 bytes. The two-job probes take
2.269–27.334 seconds and peak at 26,025,984–120,745,984 bytes. Retention adds no GPU
replay pass, but retains more data in the parent presentation. These observations
are not a leak test or P8 performance acceptance.

## Remaining scope

This change addresses the observed storage omission with an explicit native
option. It does not qualify all formats, streams, deferred-context cases, sparse
hardware signatures or workflows. The original shader-source fixture is still
needed for the two legacy main-window test rows. Full CLI presentation parity,
P3 acceptance, original fragment history, complete shader debugging, the original
GPA debugger engine, P7 removal and P8 standalone release acceptance remain open.
Existing historical failures and saved outputs are unchanged.
