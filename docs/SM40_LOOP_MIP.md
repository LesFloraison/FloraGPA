# SM4.0 mip-count queries across loops

Reviewed 2026-10-08. This M4 change removes four demonstrated false
missing-MinLOD rejections by following checked loop backedges in the existing
dimension non-use proof. It leaves captured shaders and omitted resource state
unchanged. Producer revision: `dc4e644`; implementation: `4c429d2`.

Follow-up: [checked unconditional early returns](SM40_RETURN_MIP.md) extends
this proof on 2026-10-09. The early-return restriction below describes this
historical loop batch; conditional RETC and unverified call forms remain outside
the accepted grammar.

## Dependency proof

The [RESINFO contract](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/resinfo--sm4---asm-)
separates total mip count from dimensions affected by resource MinLOD. The
existing straight-line, IF and SWITCH proof now accepts checked LOOP/ENDLOOP,
BREAK/BREAKC and CONTINUE/CONTINUEC. IADD and UGE use the same strict immediate
register operand checks as other accepted ALU instructions.

[BREAKC](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/breakc--sm4---asm-)
targets the nearest enclosing loop or switch;
[CONTINUE](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/continue--sm4---asm-)
targets its enclosing loop. IF does not own either transfer. Conditional
transfers preserve both successors, regardless of an observed output, condition
polarity or presumed iteration count. A loop has no implicit zero-iteration
exit; its checked break edges establish exits.

Each query seeds the dimension lanes written to its temporary register. A
monotone worklist propagates the union of still-live lanes to every successor,
including earlier instructions. Sources are checked before destination writes
kill lanes. Each node gains at most four lane bits, bounding worklist insertions
to four times the instruction count. A read reachable only on the second loop
iteration therefore retains the dependency. Separate proofs cover separate
queries, including queries executed inside loops.

The existing 256-instruction and 64-combined-block limits remain. Calls, early
returns, relative/extended operands, unverified instruction forms and malformed
blocks retain the dependency. SWITCH still requires a direct unconditional
BREAK after each nonempty case; executable case fallthrough is not admitted.
This is a bounded dependency proof, not a complete shader validator, optimizer
or proof that an arbitrary GPU program terminates.

All eight files were generated by local GPA 2025 R1 without editing capture
contents. The frozen producer checks twelve complete 8x8 images per hardware,
WARP and injected run: 24 runs and 288 images. Saved disassembly confirms actual
loops, including nested loops and CONTINUE. Capture files and binaries remain
outside Git; the discovery registry preserves the pre-fix evidence identity.

The old package was checked twice per capture on hardware and WARP. All seven
rejected modes report `Event 23 (Draw): Resource 24: initial minimum LOD is
unresolved at this access`. Mode 33 matches the independent application on both
backends. The producer extension also passes 120 image checks for prior modes
0, 6, 12, 20 and 27; their image, DXBC and disassembly bytes remain identical.

The original private-player adapter completes repeated playback of all eight
files. Modes 32 and 33 produce a different image from the native application,
consistent with the separately recorded MinLOD diagnostic-path discrepancy.
The original player's adapter and GUI configuration are not positively matched;
these observations do not establish general GPA GUI behavior or strict
cross-implementation equivalence. Agreement for dimension-only examples does
not make omitted initial LOD recoverable.

## Regression design

Original captures run twice on each independent hardware/WARP backend. Shader
replacement tests exchange a count-only loop and a same-resource sampling loop,
checking that dependencies are recomputed. Qt alternates successful captures and
located failures, retries and compares every accepted pixel.

CPU controls cover every truncated prefix of the compiler's DXBC, malformed
lengths and operands, invalid register indices, reserved control bits, unmatched
blocks, mixed nesting limits and early returns. Explicit graphs retain a
dimension read reachable only through ENDLOOP or CONTINUE, conditional paths
that bypass a kill, nested BREAK ownership and CONTINUE through SWITCH. These
graphs are test mutations, not original capture evidence.

To generate another untouched-original set in a development environment with
the installed GPA shim, use a fresh output directory:

```powershell
cmake --build --preset release --target FloraMipCountProbe
python tools/capture_mip_counts.py --producer build/vs2022/Release/FloraMipCountProbe.exe --out artifacts/my-loop-captures --modes 28 29 30 31 32 33 34 35
$env:FLORA_LOOP_MIP_CAPTURES = "$PWD/artifacts/my-loop-captures"
```

The `resource_lod` CTest additionally needs its prior fixture environment for
the earlier modes. The new pure proof test is named `sm40LoopProofBounds`; the
new GUI row is `mipCountReplayAndRetry:sm4-loops`. Newly generated captures need
their own hashes and registry; they must not overwrite the pinned evidence.

## Acceptance and remaining scope

Six relevant serial CTest suites pass. Their retained Qt logs, with explicit
final-build runs for the two console-only suites, contain 555 passed top-level
rows without failures or skips: resource LOD 164, clones 54, pipeline creation
70, main UI 89, frame validation 173 and shader setters 5. The initial build
command named an absent `FloraCli` target and failed; the corrected target build
and subsequent final build passed. Test-only
malformed-CONTINUE and located-rejection assertions were tightened after the
first suite build; the final 164-row resource suite was rebuilt and rerun.

Package `out/FloraGPA-loop-mip-20261008/` contains 44 files. Only GUI, CLI and
Worker differ from the preceding storage-export package. Four relocated checks
pass with a Unicode/spaced directory and system-only PATH: actual Windows Qt
loop load/failure/retry, recovery, GF2 and BF1. Four packaged golden/Draw-disable
checks pass. Ordinary replay module inventories contain no GPA or Python
runtime dependencies. These are same-host checks, not clean-machine deployment.

The complete 40-suite gate passes **565 registrations / 555 unique captures**:
**526 completions / 516 unique completions**, and **39 located refusals**. This
includes 1,130 ordinary attempts, 732 control runs and 1,032 resource exports.
All 557 previous registrations retain their full preflight reports, execution
counts and deterministic images. Helldivers retains its known image variation;
the information-missing `query_sync_9` changes repeat classification within its
existing variable policy. No threshold or shader-disabling policy was relaxed.

Completion remains distinct from application fidelity. The matrix has 94
assessed passes, 32 capture-side mismatches, 16 information-missing registrations
and 423 unassessed registrations. Among completed captures, 35 registrations
retain known capture limitations. The discovery registry remains a historical
pre-fix record; [the accepted corpus](loop-mip-corpus.json) is enrolled separately.
The [baseline](loop-mip-baseline.json) pins 1,085 local evidence files, source
hashes, the development-only producer and all package hashes. Captures and
binaries are not distributed through Git.

This work does not reconstruct omitted initial MinLOD, enable arbitrary shader
control flow, expand capture-format versions or complete M3/M4/M5. Clean-host
deployment, wider sustained workflows and the existing list/resource boundaries
remain separate work. Module migration totals remain 72 ported, 117 partial and
15 pending; they are not a feature-completion percentage.
