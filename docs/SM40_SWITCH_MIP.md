# SM4.0 mip-count queries across switches

Reviewed 2026-10-08. This M4 change extends the existing acyclic dimension-lane
proof to checked SWITCH/CASE/DEFAULT/BREAK/ENDSWITCH blocks. The preceding
implementation rejects four untouched original captures whose queried texture
dimensions are unused and whose mip count does not depend on missing MinLOD.
It does not change captured shaders or reconstruct unsaved resource state.
Implementation: `6cb0893`.

## Dependency proof

The [RESINFO contract](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/resinfo--sm4---asm-)
separates total mip count from the dimension results affected by resource MinLOD.
The [SWITCH contract](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/switch--sm4---asm-)
permits nested selection and empty shared labels. A no-match path without DEFAULT
continues after the switch. The proof visits every label and that no-match path;
even a literal selector does not remove alternatives from the graph.

All edges point forward. Each BREAK targets its nearest owning switch, including
a BREAK inside an IF. Live dimension lanes from any predecessor survive at the
join. A source use is checked before a destination overwrites the same register.
A dimension read on any checked path retains the resource-LOD dependency.

The grammar retains the 256-instruction cap and counts IF and SWITCH together
against the 64-block nesting cap. Selectors require checked scalar register or
literal operands; CASE labels require distinct scalar literals, and DEFAULT is
unique. Labels must belong to the current switch. Empty labels can share a body;
nonempty cases require a direct unconditional BREAK. Executable fallthrough,
code before the first label or after a terminating BREAK, unmatched blocks,
early returns, conditional BREAK, loops, calls, extensions and unfamiliar
operands/instructions remain conservative. This is a bounded dependency proof,
not a general shader validator or optimizer.

## Regression design and scope

Original cases run twice on hardware and WARP. Replacement-shader checks move
between a count-only switch and a same-resource sampling switch, so cached
dependencies cannot be inherited from the original shader. Qt interleaves
accepted captures and located failures, retries and verifies all accepted pixels.

Parser controls cover every truncated DXBC prefix and 31 invalid/dependent
program variants: live selectors, malformed lengths/operands, duplicate labels,
crossed IF/SWITCH blocks, incorrect BREAK placement, executable fallthrough,
missing default, partial overwrites, early return and combined nesting overflow.
Separate positive controls exercise literal selectors, leading DEFAULT, a
no-default switch followed by an unconditional overwrite, and an IF-contained
BREAK after all dimension lanes are overwritten. The paired early-BREAK control
retains a dependency. Mutations are parser tests, not original-capture evidence.

Missing initial MinLOD, texture-diff pitches, pre-frame query/counter history and
retained command-list identity remain unresolved where applicable. M3/M4/M5
completion, independent clean-machine deployment and broader sustained testing
remain open. Module counts stay 72 ported / 117 partial / 15 pending.

## Complete compatibility gate

The extended gate passes 37 suites and 533 registrations / 523 unique captures:
497 native completions (487 unique) and 36 located refusals. It retains 1,066
ordinary attempts, 684 control runs and 826 resource exports. All preceding 525
registrations keep their complete preflight reports, execution counts and
deterministic images. Helldivers retains its diagnosed image variability;
`query_sync_9` changes from repeat-stable to repeat-variable under its existing
missing-completion-boundary policy. No policy, threshold or event was changed.

The first gate process stopped before the new suite: its registration script
hashed raw CRLF bytes instead of following the registry's LF-normalized hash
policy. All preceding 36 suites / 525 cases had completed. The original failed
process log, gate and suite configuration are preserved. The registration hash
was corrected; the resume script verified the identical CLI and all 36 report
hashes, reran every gate assertion over the existing evidence, then executed and
checked the eight new cases. The final result is a verified resumed gate, not a
claim that the first invocation exited successfully. Runtime behavior and
validation requirements were not relaxed.

Fidelity remains a separate axis: 65 registrations have passed application
assessments, 32 retain capture-side mismatches, 13 lack required capture
information and 423 remain unassessed. Thirty-five completed cases have known
capture limitations. Gate success does not establish faithful application
reproduction for all 497 completed cases.

The [baseline](switch-mip-baseline.json) pins 976 evidence files, the interrupted
and resumed gate, source, test executables, package and captures. The additional
three refusals are newly enrolled information-missing controls; they are not
regressions of previously accepted files. The module ledger is unchanged.
